RECOMMENDED REPAIR ORDER
1. Close the SSH, face API and WebView trust gaps; enforce safe motion inputs and guards.
2. Fix per-action/per-session lifetimes, navigation terminal paths and transactional map saves.
3. Add protocol/database/tracker regression tests and repair the seven reproduced Python defects.
4. Repair session setup/settings, audio/camera lifecycle and event-rule behavior.
5. Align deployment scripts and make CI catch these failures; then remove verified dead code.

Regression scenarios should cover old/new connection callbacks, A/B movement timers, failed
ability holds, cancellation before localization, New Chat during a long tool, multiple tool
results arriving out of order, permission grant after startup, very short/end-of-stream audio,
camera cancellation while opening, rule import failure, and concurrent face registrations.

INTERPRETATION NOTES
- The documented half-duplex microphone behavior while Pepper speaks is intentional and is
  not classified as a bug here.
- Lint's TrustAllX509TrustManager warning points inside a BouncyCastle dependency. This review
  did not establish a reachable app TLS-bypass path, so it is not reported as such. The explicit
  SSH PromiscuousVerifier use is separately established in F01.
- OldTargetApi and GradleDependency notices alone are not proof of broken behavior. Pepper's
  Android 6 constraints must be considered before blanket SDK/dependency upgrades.
- Passing mocked/state-focused tests does not cover real camera/audio/robot action lifetimes.
- No claim is made that current provider/model availability, every external API contract, or
  all hardware/firmware combinations have been exhaustively integration-tested.
